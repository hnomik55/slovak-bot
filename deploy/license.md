# Ключи доступа и подписки

Бот платный: доступ открывается **одноразовым ключом**. Ключ привязывается к
Telegram-аккаунту покупателя и больше не нужен — доступ работает автоматически.

Это готовая основа для продажи: ты генерируешь пачку ключей, продаёшь их,
каждый покупатель активирует свой.

---

## Команды администратора

| Команда | Что делает |
|---|---|
| `/admin_key make 10 30` | 10 ключей, доступ на 30 дней |
| `/admin_key make 5 0` | 5 бессрочных ключей |
| `/admin_key make 20 30 почта` | 20 ключей на 30 дней с пометкой (для учёта) |
| `/admin_key list` | последние 30 ключей и их статус |
| `/admin_key unused` | только свободные (готовые к продаже) |
| `/admin_key revoke SLOV-XXXXX-...` | отозвать ключ (доступ у покупателя сразу пропадёт) |
| `/admin_key subs` | список подписчиков с датами окончания |
| `/admin_key extend 123456789 30` | продлить подписку на 30 дней |
| `/admin_key stats` | сводка: всего / использовано / активных |
| `/admin_user 123456789` | карточка одного пользователя |

Формат ключа: `SLOV-XXXXX-XXXXX-XXXXX` (15 символов, алфавит без похожих
0/O и 1/I — покупатель не ошибётся при переписывании).

## Как это работает для покупателя

1. Открывает бота → видит «Введи ключ доступа».
2. Присылает ключ в чат (или вводит его в приложении).
3. Ключ погашается: `used_by` записывается, у покупателя появляется подписка.
4. Дальше бот работает без ключей. Если подписка ограничена по сроку — при
   истечении бот снова попросит ключ.

Ключ, попробованный второй раз, выдаёт: «Этот ключ уже использован другим
человеком» — и в чате, и в приложении.

## Индивидуальный прогресс

Прогресс привязан к `telegram_id`, поэтому у каждого покупателя своё:

| Таблица | Что хранится |
|---|---|
| `users` | уровень, XP, серия дней |
| `lesson_progress` | какие уроки пройдены и с каким результатом |
| `user_words` | карточки SRS: интервалы, сложность, что забываешь |
| `attempts` | каждое задание: ответ, эталон, тег ошибки |
| `error_tags` | твои типовые ошибки (`diacritics`, `verb_form`…) |
| `daily_stats` | история по дням |
| `writing` | написанные работы |

Изоляция прогресса проверяется тестом `tests/test_license.py`.

## Настройки (.env)

```
OWNER_BYPASS_LICENSE=1     # 1 — владелец (ADMIN_IDS) работает без ключа
LICENSE_WELCOME=...        # текст, который видит человек без доступа
```

Чтобы **проверить сценарий с ключом на себе**, поставь
`OWNER_BYPASS_LICENSE=0`, перезапусти бота и напиши `/start` — бот попросит
ключ. Выдать себе ключ: `/admin_key make 1 0`, затем ввести его в чат.

## Приложение (Mini App)

Приложение проверяет лицензию так же, как чат:
* `/api/session` возвращает блок `license` (`active`, `plan`, `expires_at`);
* без активной подписки остальные эндпоинты отвечают `403 license_required`;
* `/api/redeem` активирует ключ прямо из приложения.

Если подписка истекла, приложение показывает экран ввода ключа, а не «нет связи».

## Что стоит добавить перед продажей

* **Оплата**: подойдёт Telegram Payments (крипта/карты) или простой перевод
  ключа вручную. Сейчас продажа ручная: ты выдаёшь ключ, покупатель активирует.
* **Пробный период**: `/admin_key make 100 7` — неделя бесплатно, потом
  нужен платный ключ.
* **Реферальная программа**: колонка `note` в таблице `licenses` уже позволяет
  записывать, по какой ссылке пришёл покупатель.
* **Статистика продаж**: `licensing.stats()` даёт всего/использовано/активных;
  добавь выручку по batch-группам, если будешь считать вручную.
